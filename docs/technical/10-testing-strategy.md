## Levels

| Level | Scope | Tooling | Runs on |
|---|---|---|---|
| **Unit** | domain ring: state machines, policies, budgets, cost math, redaction, config merge, markdown→ADF, template validation | Vitest 5 project `unit`; fast-check property/model-based tests (`fc.commands`) for the task/run/question state machines (every event sequence leaves a legal state; iteration limits and WIP limits never exceeded; budgets never overspent) | every PR, pre-push hook |

*Property seeds (WP-73c, WP-97):* **every fast-check property in the gate runs on one fixed seed** — the decision is stated here, PROGRESS backlog 270's first half. WP-73c fixed it for `packages/domain` alone, by an import each file had to remember, and the ten property files outside it kept drawing fresh seeds; since WP-97 the seed is set by a vitest **setup file** (`test/support/property-seed.ts`, the decision in `scripts/property-seed.mjs`) in every project, so no package can forget it and `contracts`, which the dependency rule gives no workspace import, gets it without one. `scripts/property-seed.test.ts` asserts the seed reaches a file that imports nothing to get it, holds the setup file to every project, and refuses a file that sets its own (`fc.configureGlobal`, or a `seed` key beside an `fc.assert`). The reason is the coverage ratchet: a figure that moves by itself flaps a gate that reads it, and two full runs of the WP-97 tree moved **no** file's covered count. The price is exploration — a gate run meets only the draws the last one met, and the nightly `--repeats` flake policy repeats identical draws — and it is bought back **out of the gate**: `.github/workflows/property-exploration.yml` runs every property file weekly (and on dispatch) on a **fresh** seed (`pnpm run -s properties:explore`, `scripts/property-exploration.mjs`), printing the seed before the run, in its verdict line and in the step summary, and on a failure the command that replays it (`pnpm run -s properties:explore --seed <n>`, or `PROPERTY_SEED=<n> pnpm exec vitest run <file>` for one file). It is scheduled, not a required check and never a pull-request gate: a counterexample it finds is a red run somebody turns into an example test.

## Fixtures and fakes (first-class code)
- `FakeClaudeRunner`: replays `test/fixtures/claude/<scenario>.jsonl` (our normalised `RunEvent`s incl. a `result` with usage/cost/`structured_output`); scripted `ask_human`, tool policy prompts, budget stops, stalls; used by application tests, the UI dev server and the e2e job.
- `Fake<Type>` providers: in-memory Jira/GitLab/Slack/Sentry/Loki with webhook emitters; exported from the integration packages, each with a divergence register in its docblock. They are test doubles only: **shadow mode** is a guard inside `IntegrationActionExecutor` (technical/06 § "Outbound: actions"), not a null adapter that replaces a provider, so nothing in the product path swaps an adapter for a fake.
- Recording tools: `pnpm record:claude --scenario feature-happy-path` (real SDK run → scrubbed fixture). Fixtures must contain only obviously fake secrets; a gitleaks rule scans `test/fixtures/**`.
- **How replay works, amended at WP-09.** This section previously named nock and `pnpm record:http` (nock.back record with a redaction hook). Neither survived contact with the first provider: the work package had no GitLab instance to record against, so every fixture is transcribed from the vendor's published documentation, and a hand-built document is what it is whatever library replays it. Two things followed. **The transport is injected** (`createGitLabProvider({fetchImpl})`), so a replay run needs no HTTP interception at all, opens no socket and can assert on the exact request that was *sent* — which is how "a mutating action in shadow mode issues zero HTTP requests" is asserted rather than assumed. And **each recorded interaction carries its provenance**: the documentation URL, the date it was retrieved, and whether the shape is `documented` (a published example or attribute table) or `inferred` (the documentation does not state it). A fixture you invented and one you recorded are different kinds of evidence, and a format that cannot tell them apart is how a provider adapter passes its own tests and fails in production. See `test/contract/support/integrations/gitlab-replay.ts`. A live recorder, when one is wanted, records into the same format. **Generalised at WP-11**: the same machinery, with the GitLab-shaped parts removed, is `test/contract/support/integrations/http-replay.ts`, which the Sentry and Loki runners share — a key built from a method and a path, a queue per key, a request log, and the two corpus checks below. It knows no vendor, and each provider's harness keeps its own vendor-shaped decisions; `gitlab-replay.ts` was deliberately **not** refactored onto it, because rewriting a landed, 32-assertion harness to prove a point about reuse puts WP-09's guarantees inside WP-11's diff. It adds one member the GitLab version has no need for: an interaction may carry a `variant`, served only once the harness activates it, which is how a *write* changes what the next *read* answers (Sentry's `resolve` issues a `PUT` and then re-reads) without the second state becoming mutable harness state that no provenance check can see. The corpus is held to the suite by two checks, and it takes both: every recorded interaction must be *reached* by some request (`unusedFixtures`), and every serve must be *followed by an assertion* in the same test (`unassertedFixtureServes`) — because deleting every `expect` from a test while keeping the calls that fetch its fixtures passed the first check unchanged. Neither proves the assertion is about the response; that limit is stated where the check is defined rather than left to be discovered.
- Golden transcripts cover: sub-agents, compaction, denied tools, budget stop, structured output failure, steer, interrupt.

## Coverage and gates
- Thresholds in `vitest.config.ts`, **per ring and with no global threshold** (WP-70, PROGRESS backlog 87): the bar is 80 % on every metric, and the domain's 90 % lines / 85 % branches / 90 % functions / 90 % statements. A ring whose measured figure clears the bar by the slack — two points or two items, whichever is larger — is held to the bar; one that does not is held to `floor(measured − slack)` and carries an `owes` line naming the files the debt is in. `COVERAGE_RINGS` is the table and `scripts/coverage-budget.test.ts` holds it as a partition: every file coverage counts matches exactly one ring's glob, by vitest's own `picomatch`. There is no global threshold because vitest counts every file into it even when a glob already holds it, so a global number puts every ring's noise and debt into every other ring's gate — it read 80.02 % against 80 when WP-70 opened. `coverage.include` is explicit; `coverage.exclude` names four source files, each a census entry (`COVERAGE_EXCLUDED_FILES`) that says which file drives it and in which tier — only the `process` and `unit` tiers are inside `verify`, and both start the file as a subprocess, which reports no coverage back. Codecov for visibility (not required).
- **The pinned floors** (WP-97, PROGRESS backlog 254) — the four thresholds `COVERAGE_RINGS` sets per ring, pinned here. `scripts/coverage-budget.test.ts` holds the configuration to this table **in both directions**, so a floor cannot be lowered (or raised) by editing one number: the edit is made in both places, with the measurement that justifies a lowering written in PROGRESS.md. The last column is the reading the floors were last set from — `unit`+`contract`+`process`, `json-summary`, branches covered / total — and is a record, not a gate.

- **The ratchet** (WP-97, PROGRESS backlog 254): `pnpm run -s coverage:ratchet` (`scripts/coverage-ratchet.mjs`) is the second step of `verify:tests`, so it runs in CI's `unit + contract` job — **where coverage is measured, never in the census**, because a measured figure exists only after a coverage run. For each ring and metric it computes the figure vitest compares with the threshold and fails when the figure is **below its floor**, or when the ring has **earned a higher floor** — `min(bar, floor(measured − slack))`, WP-70's setting rule read backwards — and the floor was not re-pinned. With two points of slack that is as soon as the figure clears its floor by three; a ring held at the bar cannot fail upwards. It refuses a `coverage/coverage-summary.json` that is not this run's: written before the target started (`scripts/verify.mjs` hands every step `VERIFY_TARGET_STARTED_AT`), missing a file this checkout counts, or listing one outside it — two runs in one checkout share that directory, and the residual (a second full run of the same tree finishing between the write and the read) is stated in the script. Its first reading re-pinned four floors WP-70's rule had already earned and nobody had raised: server branches 54 → 55, functions 50 → 52, statements 62 → 63, launcher functions 76 → 78.

  **Where the values land** (rules 57 and 64), measured over two full `pnpm test` runs of the WP-97 tree at one-minute loads of 10.6 and 11.7: **no file's covered count moved** in any metric (566 files; before WP-97 every property outside `packages/domain` drew a fresh seed). So neither trigger flaps on noise, and the distances are pure headroom. Downwards, the tightest are launcher functions (81.81 against 78: **2** functions — two items of slack), infrastructure functions (876 / 1321 = 66.31 against 66: **4** functions — corrected by WP-97's review) and infrastructure lines (79.78 against 79: **40** lines); in the two debt rings' branches, server has 67 and infrastructure 36. Upwards — the ratchet asking for a re-pin — the nearest are server lines (**5** more covered lines earn 64), launcher functions (**1** more function earns 79) and server functions (**6**). That is the ratchet working, not noise: a change that covers them re-pins in the same diff.
- Required checks on `main` (ruleset + merge queue): lint, typecheck, unit, contract, integration, e2e-fake-claude, ui, dco, commitlint.
- Flake policy: `--repeats` nightly; a flaky test is quarantined with an issue within a day.
