# Research: integration tooling (Jira, GitLab, Slack, Loki, Sentry, MCP vs CLI)

> Verified 2026-09-08/09 against official docs and release APIs. Versions: glab 1.117.0, jira-cli 1.7.0, Loki/logcli 3.7.7, mcp-grafana 1.3.0. Items still tagged `[unverified]` are listed in `TODO.md`; everything else was verified against the linked sources (second pass 2026-08-28).

## Summary matrix

| System | Platform (deterministic orchestration) | Agent (exploratory, inside a run) | Avoid / secondary |
|---|---|---|---|
| Jira Cloud | REST v3 thin client (basic auth email:API token); admin webhook or Automation "Send web request"; JQL polling fallback | `acli` (official, Cloud only, `--json`) wrapped in a skill | Atlassian Remote MCP for agents (≈50 tools, unpublished rate limits, admin enablement) |
| Jira Data Center | REST v2 (PAT bearer) | `jira-cli` (`JIRA_AUTH_TYPE=bearer`) | `acli` (Cloud only) |
| GitLab | REST v4 thin client + project/group webhooks (MR, pipeline, note events) | `glab` (MIT, static binary, `glab api` passthrough) via a skill | Official GitLab MCP (OAuth with dynamic client registration only, beta; no headless token auth) |
| GitHub (future) | REST/`gh api` behind the same provider contract | `gh` | GitHub MCP (large tool surface) |
| Slack | Bolt in Socket Mode (no public URL) + Web API; Block Kit buttons + thread replies for Q&A | No Slack credentials for agents; a platform-provided `ask_human` tool | Official Slack MCP (user OAuth, admin approval; not a bot identity) |
| Loki | Usually nothing; optional pre-fetch of a log excerpt into the task context via HTTP API | `logcli` with env auth + a skill of LogQL recipes | `mcp-grafana` only when Loki is reachable only through Grafana (then disable all other tool groups) |
| Sentry | REST thin client with an Internal Integration token; Sentry webhooks | `sentry-mcp` (small tool set, Seer root-cause) on SaaS; thin REST script on self-hosted | `sentry-cli` for reading issues (it only lists/resolves/mutes) |

## Jira

- **`acli`** (Atlassian CLI): official; `jira workitem view/edit/create/transition/comment-create/search …`, `--json`, `--yes`; auth by API token via stdin; static binary at `https://acli.atlassian.com/linux/latest/acli_linux_amd64/acli` (also arm64) or apt repo. Proprietary; each version supported ~6 months; **Cloud only** (DC page 404s). `transition` takes only `--status "<name>"`: no transition id, no fields/resolution, no comment on transition.
  https://developer.atlassian.com/cloud/acli/guides/install-linux/ , https://developer.atlassian.com/cloud/acli/reference/commands/jira-workitem-transition/
- **`jira-cli`** (ankitpokhrel, MIT, v1.7.0 2025-08): Cloud + Server/DC, non-interactive init, `issue view --raw`, `issue move`, `issue comment add`; tarball `https://github.com/ankitpokhrel/jira-cli/releases/download/v1.7.0/jira_1.7.0_linux_x86_64.tar.gz`. ADF not fully translated; custom fields need config. https://github.com/ankitpokhrel/jira-cli
- **Atlassian Remote MCP** `https://mcp.atlassian.com/v2/mcp` (v1 SSE sunset 2026-06-30): OAuth 2.1 or headless `Authorization: Basic base64(email:api_token)` / service-account bearer, but org admin must enable API-token auth; ≈50 tools across Jira/Confluence/Compass/JSM; rate limits unpublished, users report 429s at ~20 concurrent calls (issue #171). https://github.com/atlassian/atlassian-mcp-server
- **REST v3**: full control — transitions with fields (`POST /rest/api/3/issue/{key}/transitions` with `transition.id`, `fields`, `update.comment`), ADF comments, `GET /rest/api/3/search/jql` (`/search` is marked `deprecated: true`, "currently being removed", in Atlassian's OpenAPI spec https://developer.atlassian.com/cloud/jira/platform/swagger-v3.v3.json — verified 2026-08-28), `GET /rest/api/3/issue/{key}/transitions` returns transitions valid *now* for that issue; ids are per workflow so resolve at runtime and cache per (project, issue type). Screens with required fields (resolution) must be supplied on transition or the API returns 400 — the reason the platform must use REST, not `acli`, for transitions. Transition payload verified 2026-08-28 from the OpenAPI spec example: `{"transition":{"id":"5"},"fields":{"resolution":{"name":"Fixed"}},"update":{"comment":[{"add":{"body":{"type":"doc","version":1,"content":[…]}}}]}}`.
  https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/
- **Webhooks**: admin webhook (JQL filter, HMAC `X-Hub-Signature`, 5 retries with 5–15 min backoff, `X-Atlassian-Webhook-Identifier` for dedup) or Automation rule "Send web request" per project when no site-admin. Dynamic webhook registration API is for Connect/OAuth apps only. https://developer.atlassian.com/cloud/jira/platform/webhooks/
- **Rate limits**: points-based hourly quotas (since 2026-03-02) apply to Connect/Forge apps; API-token basic-auth traffic is on the older undocumented burst limits → handle `429` + `Retry-After` with backoff and jitter. https://developer.atlassian.com/cloud/jira/platform/rate-limiting/
- **Labels vs custom fields**: labels are global namespace, no validation, cheap in JQL (`labels = agentic`); a select-list custom field ("Agent status") is admin-controlled and reportable. Both CLIs need the raw `customfield_NNNNN` id.
- **Comment format**: Cloud v3 requires ADF (`{"type":"doc","version":1,"content":[…]}`) → the platform needs a small markdown→ADF converter (paragraph, codeBlock, bulletList, link marks). DC uses `/rest/api/2/` with wiki markup and PAT bearer.

## GitLab

- **`glab`** (MIT, v1.117.0 2026-09-08): `mr create --title --description --source-branch --target-branch --fill --yes --label --reviewer --remove-source-branch`, `mr note create --reply <discussion-id>`, `mr view/list/diff/approve/merge`, `ci view/status/trace/get`, `glab api` (REST v4 + GraphQL, `--paginate --output ndjson`, `--hostname`). Auth: `GITLAB_TOKEN` + `GITLAB_HOST` env, no login step. `.deb` at `https://gitlab.com/gitlab-org/cli/-/releases/v1.117.0/downloads/glab_1.117.0_linux_amd64.deb`. Works with gitlab.com, Self-Managed, Dedicated. https://docs.gitlab.com/cli/
- **Official GitLab MCP** (`https://<host>/api/v4/mcp`, beta since 18.6): ≈44 tools incl. MR, diffs, notes, pipelines, job traces, `save_merge_request_review`, `semantic_code_search`; OAuth 2.0 with dynamic client registration or pre-registered app; no PAT/bearer header documented → poor fit for headless containers. https://docs.gitlab.com/user/model_context_protocol/mcp_server/
- **Community `zereight/gitlab-mcp`** (MIT, PAT via env, 60+ tools) — headless-friendly but huge surface; unnecessary given `glab`.
- **Webhooks**: project or group hooks (`X-Gitlab-Event`, `X-Gitlab-Token` secret). MR events `object_attributes.action ∈ open/update/approved/unapproved/merge/close/reopen`; pipeline events `object_attributes.status ∈ pending/running/success/failed/canceled/skipped`; note events for comments. Group webhooks need Premium on gitlab.com. Payloads include the acting user (`user.username`, `user.email`) and Note events include `object_attributes.id` and `discussion_id` for threaded replies (verified 2026-08-28). Draft MRs "run the same pipelines as merge requests marked as ready" (https://docs.gitlab.com/user/project/merge_requests/drafts/) and pipeline webhooks fire on any status change, so the CI gate works for draft MRs. Resolving a discussion: `PUT /projects/:id/merge_requests/:iid/discussions/:discussion_id` with `resolved=true` requires Developer+ role, which a project access token's bot user has (verified 2026-08-28, https://docs.gitlab.com/api/discussions/). https://docs.gitlab.com/user/project/integrations/webhook_events/
- **Tokens**: PAT (user-bound; simplest on Free with a dedicated bot user); project access token (bot user scoped to one project; Premium/Ultimate on gitlab.com, any tier self-managed; max 400 days; scopes `api`, `read_api`, `write_repository`); group access token spans a group — best for multi-project on Premium/self-managed. Bot-authored MRs cannot self-approve when rules forbid author approval. Push via `https://oauth2:${GITLAB_TOKEN}@host/group/repo.git`. https://docs.gitlab.com/user/project/settings/project_access_tokens/
- **GitHub later**: `gh` (MIT; apt repo `https://cli.github.com/packages`; `GH_TOKEN`; `gh api --paginate`). Provider contract to implement twice: `open_change`, `comment`, `get_change`, `get_ci_status`, `list_changed_files`, `webhook_normalize`, `verify_webhook`; map MR⇄PR, note⇄comment/review comment, pipeline⇄check_suite/workflow_run. https://github.com/cli/cli/blob/trunk/docs/install_linux.md

## Slack

- **Bolt** (Python `slack_bolt` / JS `@slack/bolt`) in **Socket Mode**: bot token `xoxb-` + app-level token `xapp-` with `connections:write`; no public URL; "up to 10 open WebSocket connections at the same time"; "not currently allowed in the public Slack Marketplace" (verified 2026-08-28; fine for an internal app). Events API (HTTP) alternative if the platform already exposes a public endpoint for Jira/GitLab webhooks; must ack within 3 s. https://docs.slack.dev/apis/events-api/using-socket-mode/
- **Official Slack MCP** (`https://mcp.slack.com/mcp`, GA 2026-02-17): user OAuth, workspace-admin approval; user identity, not bot → unsuitable for a headless bot. https://docs.slack.dev/ai/mcp-server/
- **Rate limits**: Web API tiers 1–4 (≈1, 20, 50, 100 per minute per method per workspace); `chat.postMessage` ≈1 msg/s/channel. Since 2025-05-29 `conversations.history/replies` are limited to 1 req/min and 15 objects for commercially distributed non-Marketplace apps; **internal customer-built apps are exempt**. https://docs.slack.dev/apis/web-api/rate-limits/ , https://api.slack.com/changelog/2025-05-terms-rate-limit-update-and-the-marketplace
- **Q&A pattern**: post question in the task's thread with Block Kit `section` + `actions` buttons (`action_id="answer"`, value `<question_id>|<choice>`) plus "or reply in this thread"; handle `block_actions` (ack ≤3 s, `chat.update` to replace buttons); subscribe to `message.channels`/`message.groups` and match `thread_ts`; modal via `views.open` for structured multi-field input; persist `(channel, ts) → question_id`. https://docs.slack.dev/interactivity/handling-user-interaction/
- **Minimal manifest (Socket Mode)**: bot scopes `chat:write, channels:history, groups:history, channels:read, groups:read, users:read, reactions:write, files:write, app_mentions:read`; `socket_mode_enabled: true`; interactivity enabled; bot events `message.channels, message.groups, app_mention`. Create from manifest in UI or `apps.manifest.create`. https://docs.slack.dev/app-manifests/configuring-apps-with-app-manifests/

## Grafana Loki

- **`logcli`** (AGPL-3.0, match Loki version; v3.7.7 `.deb` at `https://github.com/grafana/loki/releases/download/v3.7.7/logcli_3.7.7_amd64.deb`): `query` (`--since`, `--from/--to`, `--limit`, `-o jsonl`, `--tail`), `instant-query`, `labels`, `series`, `detected-fields`, `stats`, `volume`. Env: `LOKI_ADDR`, `LOKI_USERNAME`/`LOKI_PASSWORD`, `LOKI_BEARER_TOKEN[_FILE]`, `LOKI_ORG_ID`. https://grafana.com/docs/loki/latest/query/logcli/
- **HTTP API**: `/loki/api/v1/query_range`, `/query`, `/labels`, `/label/{name}/values`, `/series`, `/detected_fields`, `/patterns`; `X-Scope-OrgID`; default `limit=100`. https://grafana.com/docs/loki/latest/reference/loki-http-api/
- **`mcp-grafana`** (Apache-2.0, v1.3.0): Loki tools `query_loki_logs`, `list_loki_label_names/values`, `query_loki_stats`, `query_loki_patterns`, `analyze_loki_labels` plus Prometheus/dashboards/alerting/incidents/OnCall/Sift (`--disable-<category>`, `--loki-enforced-matchers`); auth `GRAFANA_URL` + `GRAFANA_SERVICE_ACCOUNT_TOKEN`. https://github.com/grafana/mcp-grafana
- **Grafana Cloud auth**: username = numeric stack id, password = Access Policy token with `logs:read`; access-policy tokens do not work on the Grafana HTTP API and service-account tokens do not work on Loki directly. https://grafana.com/docs/grafana-cloud/security-and-account-management/authentication-and-permissions/access-policies/
- **Debugging recipes for the skill**: `logcli labels`, `logcli series '{app="api"}' --since 24h`, range query around the Sentry timestamp ± 5 min filtered by request/trace id, `| json | level="error"`, `instant-query 'sum by (level) (count_over_time(... [15m]))'`, `detected-fields`. Rule: always constrain time range and `--limit`, filter by id first, aggregate before reading raw lines, pipe through `jq`.

## Sentry

- **`sentry-cli`** (BSD-3): releases/sourcemaps/debug files/monitors; `issues list/resolve/mute/unresolve` only — **no issue detail or stack trace**. https://docs.sentry.io/cli/installation/
- **`sentry-mcp`** (official, FSL-1.1-Apache-2.0, active): hosted `https://mcp.sentry.dev/mcp` (OAuth, or headless with header `Authorization: Sentry-Bearer ${SENTRY_ACCESS_TOKEN}` — the worker forwards the token without storing it; verified 2026-08-28 in the README; whether an Internal Integration token is accepted there is `[unverified]`, the README only mentions user tokens) or stdio `npx @sentry/mcp-server@latest --access-token=… [--host=… --insecure-http --disable-skills=seer]`; compact tool set: `find_organizations`, `find_projects`, `search_issues`, `search_events`, `get_sentry_resource`, `update_issue`, `analyze_issue_with_seer`, `search_sentry_tools`, `execute_sentry_tool`; AI search tools need an `OPENAI_API_KEY`/`ANTHROPIC_API_KEY`; Seer is SaaS-only. https://github.com/getsentry/sentry-mcp
- **REST**: `GET /api/0/organizations/{org}/issues/?query=…`, `GET /api/0/issues/{id}/`, `GET /api/0/issues/{id}/events/latest/` (stack trace, breadcrumbs, tags), `PUT /api/0/issues/{id}/` (resolve/assign), `/api/0/issues/{id}/notes/`. https://docs.sentry.io/api/
- **Tokens**: organisation auth tokens are CI-oriented (releases), not for reading issues; user tokens die with the user (what stdio `sentry-mcp` expects); **Internal Integration tokens** are org-bound with editable scopes (`event:read`, `event:write`, `project:read`, `org:read`, `member:read`) and get webhooks → right choice for the platform. https://docs.sentry.io/account/auth-tokens/
- **Webhooks** (Internal Integration): issue created/resolved/assigned, error, comment, alerts; `Sentry-Hook-Signature` HMAC-SHA256. https://docs.sentry.io/organization/integrations/integration-platform/webhooks/
- **Rate limits**: per caller-endpoint fixed window + concurrency; headers `X-Sentry-Rate-Limit-*`; docs recommend webhooks over polling. https://docs.sentry.io/api/ratelimits/

## MCP in headless Claude Code, and CLI vs MCP

- Config: `.mcp.json` (project), `~/.claude.json`; headless `--mcp-config <file|json>` (repeatable) + `--strict-mcp-config`; `--bare` skips hooks/skills/plugins/`.mcp.json`/CLAUDE.md and needs `ANTHROPIC_API_KEY`. Transports `http` (recommended; `headers` with `${VAR}` expansion; `headersHelper`), `stdio`, `sse` (deprecated). OAuth-only remote servers require an interactive `claude mcp login` → avoid in containers. Tool naming `mcp__<server>__<tool>`; `--allowedTools "Bash(glab *),Bash(logcli *),mcp__sentry__*"`; `--permission-prompts none` removes `AskUserQuestion` → our `ask_human` must be our own tool. `system/init` in `stream-json` reports `mcp_servers`/`mcp_server_errors`. Tool Search on by default → only tool names in context up front; `MAX_MCP_OUTPUT_TOKENS` default 25k. https://code.claude.com/docs/en/mcp , https://code.claude.com/docs/en/headless
- Evidence: CLIs use 4–32× fewer tokens per operation than MCP in community benchmarks; Anthropic "Code execution with MCP" shows progressive disclosure cutting 150k → 2k tokens; "Agent Skills" load only name+description until invoked; "Writing tools for agents" recommends few consolidated tools with concise/detailed response modes. https://www.anthropic.com/engineering/code-execution-with-mcp , https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills , https://www.anthropic.com/engineering/writing-tools-for-agents , https://kaxil.substack.com/p/mcp-vs-cli-vs-rest , https://www.firecrawl.dev/blog/mcp-vs-cli
- **Pattern adopted (BD-017, product/08)**: platform = plain code against REST + webhooks + Slack Socket Mode, no LLM in the deterministic path; agent = Claude Code with CLIs on PATH, one skill per system (5–10 recipes), one platform-owned stdio MCP (`ask_human`, `report_progress`, `get_task_context`, `kb_search`), at most one third-party MCP (`sentry-mcp`); agents hold read-mostly scopes, the platform holds transition/merge/Slack credentials.

## Docker install (Debian/Ubuntu, amd64; arm64 variants noted)

```dockerfile
ARG GLAB_VERSION=1.117.0 JIRA_CLI_VERSION=1.7.0 LOKI_VERSION=3.7.7 MCP_GRAFANA_VERSION=1.3.0
# acli:   https://acli.atlassian.com/linux/latest/acli_linux_amd64/acli  (or apt repo https://acli.atlassian.com/linux/deb)
# jira:   https://github.com/ankitpokhrel/jira-cli/releases/download/v${JIRA_CLI_VERSION}/jira_${JIRA_CLI_VERSION}_linux_x86_64.tar.gz
# glab:   https://gitlab.com/gitlab-org/cli/-/releases/v${GLAB_VERSION}/downloads/glab_${GLAB_VERSION}_linux_amd64.deb
# gh:     apt repo https://cli.github.com/packages (keyring githubcli-archive-keyring.gpg)
# logcli: https://github.com/grafana/loki/releases/download/v${LOKI_VERSION}/logcli_${LOKI_VERSION}_amd64.deb
# mcp-grafana (optional): https://github.com/grafana/mcp-grafana/releases/download/v${MCP_GRAFANA_VERSION}/mcp-grafana_Linux_x86_64.tar.gz
# sentry-cli: curl -sL https://sentry.io/get-cli/ | sh ; sentry-mcp: npm i -g @sentry/mcp-server
# Claude Code: bundled by the Agent SDK (npm/pip) or npm i -g @anthropic-ai/claude-code
```
Runtime env expected: `GITLAB_TOKEN`, `GITLAB_HOST`; `GH_TOKEN`; `JIRA_API_TOKEN` (+ `JIRA_AUTH_TYPE=bearer` for DC); `LOKI_ADDR`, `LOKI_USERNAME`/`LOKI_PASSWORD` or `LOKI_BEARER_TOKEN`, `LOKI_ORG_ID`; `SENTRY_AUTH_TOKEN`, `SENTRY_URL`, `SENTRY_ORG`; `SENTRY_ACCESS_TOKEN` for `sentry-mcp`.

## Caveats
- Atlassian ACLI is Cloud-only; DC support requires `jira-cli`.
- `acli` non-interactive login from stdin is documented for CI (https://developer.atlassian.com/cloud/acli/guides/use-acli-on-ci/); where it stores the session on disk and any env-var alternative are not documented `[unverified]` → re-run the login at container start.
